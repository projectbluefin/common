# Repo Map — On-Device Agent Bundle

**Summary:** This map shows where everything in this bundle came from and where
the editable source lives, so an on-device agent can tell a read-only snapshot
from the source-of-truth repository. The bundle at
`/usr/share/ublue-os/agent/` is generated from `projectbluefin/common`; the
arrows point from each bundle file to its source skill.

## Bundle contents

| File in the bundle | What it is | Source |
|---|---|---|
| `AGENTS.md` | On-device reading of the repo contract (hand-written, not generated) | `AGENTS.md` (scoped down) |
| `SKILL.md` | Task→skill router (hand-written, not generated) | `docs/SKILL.md` (scoped down) |
| `index.json` | Generated catalog of exactly the on-device skills | generated from `docs/skills/*` front matter |
| `repo-map.md` | This file | — |
| `INDEX.md` | Lists whatever is in the drop-in `context.d/` directory | variant drop-ins |
| `skills/<id>.md` | On-device copies of the bundled skills | `docs/skills/<id>.md` |
| `context.d/` | Empty drop-in for variant context (Utah adds `10-utah.md`) | variant repositories |

## How the bundle is kept in sync

The bundle is generated by
`scripts/generate_skill_index.py`. A skill ships on-device only when its front
matter carries `scope: on-device`. Running
`python3 scripts/generate_skill_index.py --write` regenerates `index.json`, the
`skills/` copies, and the drift check. If the shipped bundle drifts from the
source, the check fails and tells you to regenerate.
